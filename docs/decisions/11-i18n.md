# Phase 11 — i18n

How the site is served in English and Spanish with Polylang free. The editorial
rule (every note exists in both languages) is in [10](10-notes.md).

See [README.md](README.md) for how entries are written.

## 2026-10-21 — URLs: translated bases, no `-es` suffix

English is the default language and has no prefix; Spanish lives under `/es/`
(Polylang directory mode). Polylang free does not translate the base of a post
type, and it cannot share a slug between two languages (the duplicate gets
`-es`). The plugin adds a small layer on top (`plugin/inc/i18n.php`):

- **Bases:** `/es/trabajo/`, `/es/servicios/` and `/es/notas/` for projects,
  services and notes. The map is filterable (`portfolio_core_url_bases`).
- **No `-es` in public URLs:** a Spanish post keeps its `-es` slug in the
  database only when it would otherwise clash. The public URL drops it when the
  shorter slug equals the English post's slug; the request is resolved back to
  the real post.
- **Output and input:** `post_type_link` / `post_link` build the Spanish URL,
  rewrite rules (`top`, because Polylang does not prefix them) accept it, and a
  301 sends the old English base under `/es/` to the translated one.
- **hreflang:** Polylang's tags plus `x-default` pointing to English.
- **Root:** the language root is `home_url( '/es/' )`, not `pll_home_url()`,
  which returns the static front page (`/es/inicio/`) and would duplicate it in
  every URL.

Cost: a layer of our own rewrite code that Polylang Pro would make unnecessary.

## 2026-10-21 — Language switcher in the header

The switcher sits in the header next to the theme toggle (`EN / ES`). It links
to the translation of the current page, falls back to the language's home when
there is none, marks the current language with `aria-current` and gives the
full language name to screen readers.

## 2026-10-21 — Related block resolves the translation at render time

The block stores the ID of the service and project in the default language. On
render, the plugin maps each ID to its translation in the current language
(`pll_get_post`). **If there is no translation, the row is skipped** rather than
showing a card in another language. A Spanish note therefore shows no Related
block until its service has a Spanish version.

## 2026-10-21 — Plugin translations: front-end strings only

`portfolio-core` loads `languages/es_ES` for the three strings the visitor sees
(Related, Service, Project). The admin UI of the plugin stays in English.
`.mo` and `.l10n.php` are committed next to the `.po`, like the theme's.

## 2026-10-21 — Canonical of the front page

Rank Math's Polylang support appends the Polylang home path to the front page
canonical, assuming WordPress at the domain root; in a subfolder the path is
repeated. The plugin sets the front page canonical to `pll_home_url()` of the
current language, the same URL the hreflang tags use, so canonical, `og:url`
and hreflang always agree. The Notes page has its own correction (see 10).

## 2026-10-21 — Breadcrumb Home label comes from the theme catalogue

Rank Math has a single "Home" label for every language. The breadcrumb filter
now sets it from the theme's translation (`Home` → `Inicio`), so the visible
trail and the `BreadcrumbList` schema are in the page's language.
